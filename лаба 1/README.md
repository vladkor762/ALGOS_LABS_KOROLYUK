# Лабораторная работа 1. Сложность алгоритмов

## Что делал

Реализовал 5 алгоритмов, замерил время работы и память через time.perf_counter и tracemalloc. Размеры массивов взял 100, 1000, 5000, 10000. Для таблицы умножения размеры меньше 10, 50, 100, 200 потому что она берет много памяти.

## Теория

| Алгоритм | время | память |
|----------|-------|--------|
| Поиск элемента | O(n) | O(1) |
| второй максимум | O(n) | O(1) |
| Бинарный поиск | O(log n) | O(1) |
| таблица умножения | O(n^2) | O(n^2) |
| Сортировка вставками | O(n^2) | O(1) |

## Замеры

| 10000 | 0.0002 | 48 |

## Вывод

Поиск элемента и второй максимум работают линейно, время растёт пропорционально n, память при этом не меняется. Это O(n) и O(1).

Бинарный поиск почти не зависит от размера, время держится около 6e-06 даже на 10000 элементах. Это O(log n). Память тоже O(1).

Таблица умножения самая тяжёлая по памяти, при n=200 занимает уже полтора мегабайта. Если размер увеличить в 2 раза то память вырастет в 4 раза, значит O(n^2) и по времени и по памяти.

Сортировка вставками на 10000 элементах работает 2.4 секунды. При увеличении n в 10 раз время выросло примерно в 100 раз, что как раз подтверждает O(n^2). Память при этом константная.

Всё совпало с теорией.
